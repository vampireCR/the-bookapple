# TheAppleBook — обновление проекта

## 1. Файлы сайта

Замените файлы сайта содержимым этого архива и отправьте изменения в GitHub Pages.
Не публикуйте `service_role` key в HTML, JavaScript или любом другом клиентском файле.


## Вход с нескольких устройств

Фронтенд сохраняет сессию отдельно в локальном хранилище каждого браузера. Поэтому можно войти в один аккаунт на компьютере, телефоне и другом устройстве: вход на одном устройстве не должен автоматически завершать вход на остальных. В Supabase Dashboard откройте **Authentication → Settings** и убедитесь, что настройка **Single session per user** выключена (если она доступна в вашем тарифе/интерфейсе). Не нажимайте «Выйти» на одном устройстве, если хотите оставить его авторизованным.

Supabase может применять собственные ограничения безопасности и срок действия сессий; клиентский код не может отменить серверную политику проекта.

## 2. База данных Supabase

1. Откройте Supabase → SQL Editor.
2. Выполните `supabase/migrations/20261123_complete_features.sql` целиком.
3. Если SQL Editor покажет ошибку, остановитесь и сохраните полный текст ошибки — не запускайте файл частями наугад.

Миграция добавляет поля профиля, приватные настройки, присутствие, Notes, комментарии, кошелёк, подарки, ежедневные награды, историю просмотров, модерацию, вложения сообщений и одноразовые QR-входы.

Файл `supabase/schema.sql` — базовая схема исходного проекта. Если проект уже работает, не запускайте её поверх существующей базы: используйте миграцию выше.

## 3. Supabase Edge Functions

Установите Supabase CLI и войдите в свой проект. Из корня репозитория выполните:

```bash
supabase link --project-ref tzkxujrjrhyqxgzytaex
supabase functions deploy qr-login-create --no-verify-jwt
supabase functions deploy qr-login-poll --no-verify-jwt
supabase functions deploy delete-account
```

`qr-login-create` и `qr-login-poll` доступны без обычной пользовательской сессии, потому что QR-вход начинается на новом устройстве. Защита обеспечивается длинными одноразовыми секретами, хранящимися в базе только в виде SHA-256-хешей. Подтверждение QR выполняется только авторизованным пользователем через `approve_qr_login`.

Для QR-кода укажите адрес опубликованного сайта. В Supabase → Edge Functions → Secrets добавьте `SITE_URL` со значением `https://vampirecr.github.io/the-bookapple/` (если адрес GitHub Pages не менялся). Секрет `SUPABASE_SERVICE_ROLE_KEY` используется только внутри Edge Functions и не должен попадать в клиентский код. Если он отсутствует в окружении Edge Functions, задайте его через Supabase Secrets.

## 4. После публикации

- Откройте сайт и выполните жёсткое обновление страницы (`Ctrl + F5`), чтобы браузер получил новый Service Worker.
- Проверьте вход/регистрацию, ленту, комментарии, редактирование своих публикаций, Notes, профиль, аватар, сообщения и вложения.
- Проверьте ежедневные 250 токенов и отдельный бонус персонала.
- Проверьте QR-вход на двух устройствах. Подтверждайте QR только если шестизначный код совпадает на обоих устройствах.
- Проверьте приватность телефона: видимость выключена по умолчанию.
- Проверьте удаление аккаунта только на тестовом аккаунте: действие необратимо.

## Важные ограничения

- Миграция не создаёт и не меняет ключи проекта.
- Текущий фронтенд ограничивает интерфейс по ролям, но окончательные права всегда проверяются RLS и SQL-функциями.
- Лимит трёх активных устройств не включён: Supabase Auth с обычной клиентской сессией сам по себе не предоставляет надёжного контроля количества браузерных сессий. Для такого ограничения нужна отдельная серверная система управления сессиями; нельзя имитировать его только JavaScript-кодом.

## Что ещё не следует считать готовым

- Переключатель языка сохраняет выбранный язык и выставляет `lang`/направление страницы; полная построчная локализация всех динамических сообщений ещё не реализована.
- Ограничение «не более трёх активных устройств» не включено. Не стоит добавлять его только на клиенте: это можно обойти. Нужен отдельный серверный session registry и Edge Function, которая отзывает лишние Auth-сессии.
